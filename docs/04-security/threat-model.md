# 04-2 权限、签名、时间与外部数据的风险

## 一张够用的威胁模型表

| 资产 / 边界 | 对手能力 | 需要验证 |
| --- | --- | --- |
| 资产提取 | 任意地址可发交易 | 是否严格限定领取者 |
| 权限控制 | 前端可被绕过 | `msg.sender` 检查是否在链上 |
| 时间依赖 | 生产者可在有限范围影响时间 | 截止时间附近边界与公平性 |
| 外部调用 | 收款方可能是恶意合约 | 重入、失败回滚、拒绝服务 |
| 签名授权 | 签名可能被重放 | chainId、nonce、deadline、domain |
| 预言机数据 | 价格可能延迟或被操纵 | 数据源、心跳、偏差、停机路径 |

## 重点易错项

### 用 tx.origin 做登录是错误类比

`tx.origin` 可被中间合约利用作钓鱼型授权；合约内部应依据直接调用者身份及明确的业务授权模型控制。

### 签名必须有上下文

EIP-712 typed data 可表达结构化消息，但不能天然阻止重放。需要在协议层设计 `nonce`、链 ID、合约域、超时与签名消费记录。

### 预言机不是同步可信 API

链上程序不能像 Flask 服务那样随意直接请求互联网。使用价格预言机需要理解响应滞后、操纵窗口、断供和清算风险。

## 作业

给 Escrow 列出恶意买家、恶意卖家、意外失败收款方、抢先交易四种角色或场景，各写一个“预期应当如何失败”的测试案例。

**验收：** 你能解释“只有 owner 才能调用”不代表合约就安全：owner 本身被盗、owner 被恶意替换、资金无法提现都可能出问题。
