# 06-2 智能合约面试自测（附参考思路）

> 面试时先说概念，再说具体代码和风险。题目是复习辅助，不是背诵标准答案。

### 1. EOA 和合约账户有何区别？

EOA 由私钥控制并主动发起交易；合约账户执行部署好的字节码。两者都可以有余额，但代码和控制方式不同。

### 2. 为什么状态写入要付 Gas？

因为网络执行和持久保存状态需要可计量资源，费用机制用于资源定价和限制滥用。

### 3. msg.sender 与 tx.origin 有什么区别？

`msg.sender` 是当前调用的直接发起者；`tx.origin` 是交易最初的外部账户。不要用 `tx.origin` 代替合约授权。

### 4. view、pure、payable 各是什么？

`view` 不修改状态，`pure` 还不能读取合约状态；`payable` 允许随调用携带原生币。

### 5. storage、memory、calldata 有何不同？

分别强调持久存储、调用中内存、外部函数参数的只读数据区域；数据位置与是否会写入链上有关。

### 6. mapping 为什么不适合遍历？

它没有可枚举的键列表；通常需要另行维护键集合或使用链下事件索引。

### 7. revert 会退还 Gas 吗？

失败会回滚本次交易中的状态变化，但已经执行的操作仍然消耗 Gas。

### 8. 哪种测试最容易漏？

只测正常路径、只测管理员自己、忽略时间/余额边界、忽略外部合约失败和恶意回调。

### 9. 何为重入？

外部合约收到控制权后，在原合约完成状态更新前再进入其函数，可能打破业务不变量。

### 10. CEI 为何有用，还不够在哪里？

先检查再改变状态，最后外部交互，减少经典重入窗口；但不能替代全局不变量检查与跨函数审计。

### 11. 为什么交易 hash 不是成功证明？

交易广播、进入区块、执行成功和最终确认是不同阶段，要查看 receipt 状态和重组风险。

### 12. ERC-20 approve 有什么风险？

授权的是 spender 的可用额度，额度过大或交给恶意 spender 会扩大资产风险。

### 13. oracle 是什么？为什么不直接 HTTP GET？

合约执行必须保持确定性，无法直接读取不确定的互联网内容；预言机引入额外信任和数据质量边界。

### 14. 合约事件有什么局限？

事件便于外部观察，但不能代替当前状态、业务权限判断或可靠最终确认。

### 15. 你做的 Escrow 最大缺陷是什么？

缺少争议仲裁与真实交付证明；若卖家拒收 ETH 则放款会失败；必须明确残余风险，不能直接投入真实资金。
