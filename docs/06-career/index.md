# 06-1 入门完成以后怎么继续：选一条路，不要同时学十个框架

> **本课目标**：做完 Escrow 后，知道自己下一阶段该学什么、怎样练习、哪些知识暂时不用碰。你不需要立刻掌握 DeFi、MEV 或跨链。

## 先检查你是否真的“学完基础”

不看前文回答：

1. 钱包、地址、私钥、合约地址分别是什么？
2. 为什么给状态加 1，和读取当前数字不是同一种操作？
3. 你能在 Remix VM 部署 Counter，切换账号复现一次权限错误吗？
4. 你能运行 `forge test -vv`，解释三条 Escrow 测试为什么通过吗？
5. 如果卖家拒收 ETH，这个教程项目能解决问题吗？

如果还有一两个问题回答不出来，**回到对应课程重做一次，比直接冲进“高阶项目”更有效**。

## 路线 A：专门做智能合约开发

适合：喜欢业务规则、权限状态机、安全测试，希望以后写合约。

建议顺序：

| 顺序 | 学什么 | 做出什么 |
| --- | --- | --- |
| 1 | 加深 Solidity 类型、映射、事件、错误 | 扩展 Counter / Notebook |
| 2 | Foundry 的不同角色与失败测试 | 自己写一条 Unauthorized 测试 |
| 3 | Fuzz 与时间、资金边界 | 检查退款边界 |
| 4 | OpenZeppelin 的标准库与角色模型 | 在测试项目演示角色限制 |
| 5 | 安全复盘 | 写一份“为什么我的合约不能管理真钱”的说明 |
| 6 | 再接触代理升级、存储布局等 | 阅读成熟项目，不急于自己创造协议 |

初学者常犯的错误是直接复制一份“DEX、DAO、发币”大项目，能运行却根本看不懂。推荐先把一个小合约的**正常路径与失败路径**讲清楚。

## 路线 B：Web3 后端 / 全栈

适合：已有 Python、Flask、数据库经验，想把合约接入产品。

先理解系统分工：

```text
网页按钮 / 钱包签名
          ↓
区块链 RPC ──调用──> Solidity 合约
          │
          └──链下后端监听事件、核对回执
                          ↓
                        数据库
                          ↓
                       业务页面
```

下一步的最小 DApp 可以做：

1. 网页连接测试钱包。
2. 读取 Counter 合约的 `count`。
3. 点击按钮发出 `increase` 交易。
4. 分别显示“等待用户签名”“交易已广播”“执行成功或失败”。
5. 读最新状态，处理用户拒绝签名、网络错误和错误链 ID。

可以用 viem 或 ethers.js，**先选一种**。后端如果记录链上事件，还要考虑确认数、重组、幂等、断点续传——这一点与你过去的异步任务/数据库经验关系很大。

本手册 v0.2 计划加入最小 viem DApp，但**当前 v0.1 并没有把完整可运行 DApp 当作已完成内容**。

## 路线 C：安全测试和审计方向

适合：喜欢找边界条件、调试、读其他人的合约代码。

你的训练顺序可以是：

1. 看懂权限、状态、时间、外部调用这四种危险点。
2. 在本地隔离环境里构造失败用例。
3. 用调用轨迹定位哪个条件没检查。
4. 写出“漏洞影响、复现步骤、修复方式、修复后测试”。
5. 后续再学签名重放、预言机异常、MEV、经济攻击。

不要在未知授权的主网合约上测试真实资金攻击。安全学习以本地与获得明确授权的环境为准。

## 应该保留怎样的作品集？

建议把你的项目 README 写成五段：

- **业务目标**：一笔订单如何存入、放款、退款？
- **技术栈**：Solidity、Foundry、测试环境。
- **架构和状态图**：四种状态、三类角色。
- **测试证据**：你实际执行的命令和结果，尤其是反向测试。
- **已知限制**：没有真实交付判定、争议仲裁和专业审计。

不要只放“编译成功”的截图；面试时能解释一个拒收 ETH 的失败场景，更能证明你理解了代码。

## 官方资料作为进一步查阅，不要一口气全啃

- [Solidity 官方文档](https://docs.soliditylang.org/)：查语法与行为。
- [Foundry Book](https://getfoundry.sh/)：查工具和测试命令。
- [Ethereum 开发者文档](https://ethereum.org/en/developers/docs/)：查交易、账户、网络概念。
- [OpenZeppelin Contracts](https://docs.openzeppelin.com/contracts/)：查标准实现。
- [OWASP Smart Contract Security](https://scs.owasp.org/)：查安全风险分类。

**完成标准**：能讲一个自己的小项目，知道它解决什么、没有解决什么，不把“本地跑通”说成“主网安全”。
