# 00-4 零基础排错手册：照着做却跑不通怎么办？

> **什么时候看**：你在 [Remix 实操课](/00-start/environment) 或 [Foundry 入门课](/03-foundry/) 遇到错误时，不用把全部知识重新学一遍。按“现象 → 原因 → 最短修复路径”查。
>
> **安全原则**：所有排错先使用 Remix VM 或本地 Foundry，不连接真实资金账户，不把私钥/助记词发给别人。

## 先确定自己在做哪一种实验

| 我现在使用什么 | 实际运行在哪里 | 需要真实钱包吗 | 需要真钱吗 |
| --- | --- | --- | --- |
| Remix + **Remix VM** | 浏览器内的虚拟链 | 不需要 | 不需要 |
| Foundry + `forge test` | 本地测试 EVM | 不需要 | 不需要 |
| Anvil | 本机运行的开发链节点 | 不需要真实账户 | 不需要 |
| Remix + Injected Provider | 浏览器钱包连接的指定网络 | 需要 | 视所选网络而定 |

**新手先选前三种。** 如果界面突然要求连接钱包或切换主网，检查是否误选了 Injected Provider。

## 一、Remix 中最常见的 7 种问题

### 问题 1：我打开了网站，却找不到“新建文件”

先在左侧找到 **File Explorer**，不要在 Solidity Compiler 里找文件。新建文件名用：

```text
Counter.sol
```

后缀 `.sol` 代表 Solidity 源码文件。文件创建后要把完整合约复制进去，**不能只粘贴函数主体**。

### 问题 2：编译器提示版本不兼容

假设源码第一行有：

```solidity
pragma solidity ^0.8.24;
```

`^0.8.24` 表示使用兼容的 0.8.x 编译器，不能随便选 0.7.x 或 0.9.x。打开 **Solidity Compiler**，选择与源码兼容的编译器，再点击 **Compile Counter.sol**。

如果编译失败，不要继续部署；先检查红色错误文本。

### 问题 3：`ParserError` 或 `Expected ';'`

Solidity 很在意括号和分号。下面是**错误示例**：

```solidity
uint256 public number
```

正确的是：

```solidity
uint256 public number;
```

若复制代码后出现奇怪符号，检查是不是把中文引号 `“ ”` 当作 Solidity 字符串的英文引号 `" "`。

### 问题 4：编译通过，为什么没有 Deploy 按钮？

到 **Deploy & Run Transactions** 面板检查：

1. **Environment** 是否选择 Remix VM。
2. **Contract** 下拉框是否选择了刚刚编译的合约。
3. 是否在前一个页面只新建文件、却没有执行编译。

注意：点击 Deploy 是**创建一个新的合约实例**。每次重新部署都会得到一个新实例，旧实例的状态不会自动复制到新合约。

### 问题 5：我点了 increment，为什么 number 不变？

按顺序排查：

1. Deployed Contracts 中是否展开了**同一个实例**？
2. 是否真正点击了 **increment**，而不是只点 `number`？
3. Remix 终端是否显示交易失败？
4. 是否切换了虚拟环境或刷新导致实例变化？

正确的观察顺序：

```text
部署 → 读 number() 得到 0
    → 点 increment()
    → 再读 number() 得到 1
    → 点 increment()
    → 再读 number() 得到 2
```

### 问题 6：`revert` 是不是代码坏了？

不一定。假设 `reset()` 只允许 owner 调用，其他账号尝试调用时，**失败恰恰是预期结果**。

判断故障先看三个问题：

- **由哪个 Account 发起**？
- **调用前合约是什么状态**？
- **错误是编译错误还是执行过程中 revert**？

如果是你设计的“无权操作应被拒绝”，测试出现 revert 反而说明权限规则生效。

### 问题 7：我刷新网页后找不到原来的合约

Remix VM 属于虚拟实验环境，不应当作为可靠持久账本。重置或切换工作区、环境等操作可能使之前的实例不再可用。

此时重新编译、重新部署，再按课文完成一次 0 → 1 → 2，不要为了找旧测试数据而连接真实钱包。

## 二、Foundry 中最常见的 5 种问题

### 问题 1：终端提示 `forge: command not found`

它不是“合约代码错了”，而是系统找不到 Foundry 可执行程序。依次检查：

1. 是否安装了 Foundry（参照 [官方安装指引](https://getfoundry.sh/introduction/installation/)）。
2. 是否重新打开终端或加载了对应的 PATH。
3. 是否在 Windows PowerShell 里误用了 Linux / WSL2 的安装步骤。

先运行：

```bash
forge --version
```

只有能输出版本信息后，再执行测试。

### 问题 2：找不到 `foundry.toml`、`src/`、`test/`

很可能不在教程示例目录。假设你已经位于仓库根目录，执行：

```bash
cd examples/foundry
```

之后应该能看到 `foundry.toml`。如果已经在 `examples/foundry` 中，**不要再执行一次相同的 cd**，否则会找不到目录。

### 问题 3：首次编译一直失败或无法下载编译器

本仓库 `foundry.toml` 使用 `solc_version = "0.8.26"`。初次运行若缺少对应编译器，可能需要获取它。

如果机器无法联网、下载失败，先确认是否处于离线环境。**不要为了修复编译器下载问题，执行来历不明的 curl/bash 一键脚本，更不需要提供任何钱包私钥。**

### 问题 4：`forge test -vv` 有 FAIL

不要立刻把测试删除、或者把 `require` 全改成 true。

试着先定位失败用例：

```bash
forge test --list
forge test --match-test testOwnerCanReset -vvvv
```

第二条命令输出更多调用轨迹。将测试名称替换成你实际看到的失败测试名。

请记录四项：

| 需要记录的内容 | 为什么 |
| --- | --- |
| 失败的测试名 | 先知道是哪条规则不满足 |
| 预期值 | 比如 count 应是 3 |
| 实际值或 revert | 判断行为与预期的差异 |
| 使用的账户与时间 | 排查权限和到期边界问题 |

### 问题 5：编译成功是不是等于合约安全？

不是。

- **编译通过**：语法、类型检查等可以生成字节码。
- **测试通过**：你写出的那些测试断言当前通过。
- **专业审计通过**：另外的完整安全评估过程。

尤其涉及真实资金时，不能用一条“测试通过”消息替代安全验证。

## 三、几个经常把新人绕晕的术语问题

### 我能否先学习 Solidity，完全不理解交易？

可以先学语法，但很快就会误解“读变量”和“改变量”的区别。建议先看 [00-1 基础故事](/00-start/) 和 [00-2 Remix 实验](/00-start/environment)，至少能区分读取调用与交易。

### 为什么源码改了、重新编译后，旧合约还是原样？

因为 **编译的是本地源码，部署的是链上的独立实例**。旧合约不会自动热更新。你需要再次部署新实例，或者以后专门学习受限的可升级架构。

### 为什么钱包显示了交易哈希，业务页面还在“等待”？

交易哈希只是交易标识；还需要检查回执、执行成功与所需确认。不要把“已经广播”当成“已经完成”。

### 合约里的 private 能保护身份证号吗？

不能。链上状态一般不应存储这类敏感内容，`private` 只限制合约代码层面的访问，**不是加密**。

### 不懂英语可以继续吗？

可以。先理解英文词在场景中的意思，不必一开始背全部单词。打开 [零基础术语词典](/00-start/glossary)，结合正在操作的按钮一起理解。

## 四、如何把错误描述清楚？

如果自己仍解决不了，可以按下面的格式记录，方便排查：

```text
我在哪一课：
使用的是 Remix VM / Foundry / Anvil：
我执行的按钮或命令：
我原本希望看到什么：
实际出现什么错误（粘贴原始错误文本）：
我刚才改过哪些代码：
```

**不要附带私钥、助记词、真实钱包恢复信息或真实资金转账材料。**

最后复习一次顺序：先确保环境对，再确保编译通过，再验证运行结果，最后才处理复杂的资金和权限问题。
