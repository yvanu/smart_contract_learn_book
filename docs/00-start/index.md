# 00-1 为什么学智能合约？

<span class="doc-lead">目标：先理解智能合约解决了什么问题、没有解决什么问题，再动手写代码。</span>

## 你已经理解的“后端服务”

在 Flask 应用里，你能修改数据库、重启服务、回滚版本，甚至手工修复某一条记录。调用者通常信任服务运营方。

智能合约的核心差异是：**多方共享同一套状态规则，状态由链上交易共同更新，执行费用由发起者承担**。一旦部署，运行中的代码不能像私有服务器上的服务那样随意替换。

| 传统后端 | EVM 智能合约 |
| --- | --- |
| Python/Java/Go 服务 | Solidity 编译成 EVM 字节码 |
| 服务器数据库 | 全网复制的链上状态 |
| 用户凭证/JWT | 私钥签名交易 + msg.sender |
| DB 事务提交 | 链上交易成功后写入状态 |
| 运维 cron 执行任务 | 必须有外部账户/合约触发交易 |
| 服务方支付服务器费用 | 交易提交者通常支付 Gas |
| 可管理员修数据 | 合约规则和授权决定能否更改 |

## 关键角色

- **EOA（外部账户）**：通常由私钥控制，可主动发起交易。
- **合约账户**：存储合约代码和状态，通常由外部交易或其他合约调用触发执行。
- **钱包**：管理密钥、展示余额和构造/签名交易的工具；不是资金真正“存放的位置”。
- **节点和 RPC**：让客户端读取链状态、广播交易；不能因为 RPC 返回结果就自动相信它无害。
- **Gas**：EVM 为计算与存储等操作计量的资源单位；Gas 价格会受网络机制影响。

## 不要踩的第一批坑

1. 私钥、助记词绝不能放进 Git、截图、日志或前端代码。
2. 链上数据通常公开可查。不要把敏感业务数据直接写到 `public` 状态变量，以为只有 owner 能看。
3. 链上“随机数”、外部行情和定时任务都不能按普通后端思路直接照搬。
4. **写了测试并不等于审计通过**。示例只用于虚拟环境和测试网。
