# 00-1 从零认识智能合约：先别急着写代码

> **适合谁**：没接触过区块链，但会一点 Python、Web 开发或数据库的人。如果连 Python 也不会，本课的故事和操作仍能看懂。
>
> **本课目标**：读完后能用自己的话解释区块链、智能合约、账户、钱包、交易、Gas，并能分清“读数据”和“改数据”。**本课不要求安装软件。**

## 先用一个生活场景理解

假设你在网上买一台二手相机，售价 100 元。你担心付了款卖家不发货；卖家担心发了货你不付款。

传统的做法是找平台担保：

1. 买家先把 100 元交给平台。
2. 平台记录“买家已付款”。
3. 卖家发货。
4. 买家确认收货。
5. 平台把 100 元转给卖家。

如果平台是一个 Flask 项目，流程可能是：

```python
@app.post("/orders/<order_id>/confirm")
def confirm(order_id):
    # 省略：验证登录身份、订单归属、付款和发货状态
    db.execute("UPDATE orders SET status = 'COMPLETED' WHERE id = ?", (order_id,))
    pay_to_seller(order_id)
    return {"ok": True}
```

这里有一个前提：**大家信任平台会按照约定执行规则**。平台管理员能改数据库，服务器可能宕机，转账服务也可能失败。

智能合约提供另一种实现方式：**把“谁能付款、谁能确认、什么情况下退款”写成程序，并部署到区块链上，由区块链网络按照同一套规则执行。**

注意：这不意味着区块链能知道相机是否真的发货，也不意味着合约天然没有漏洞。链下发生的现实事实，仍需要人、可信数据源或争议处理机制来判断。

## 先弄懂 6 个必须知道的词

### 1. 区块链：多人共同维护的账本

把它想成**许多计算机共同维护的一份账本**，而不是你自己部署的一台 MySQL 服务器。它记录交易以及执行后形成的状态。不同链有不同规则，不能把所有区块链当成同一种系统。

- 数据不是存在“你的钱包 APP 里”。
- 交易被网络接受并写入区块后，其他人可以验证相关记录。
- 已确认的记录通常不能像本地数据库那样由管理员直接改掉；但链可能出现重组，业务上仍要考虑确认状态。

### 2. 智能合约：部署在链上的程序

**智能合约是程序，不是会思考的智能 AI，也不一定是法律合同。**

它更像一个带持久数据的后端模块：有函数，也有自己的状态，其他账户或合约可以根据网络规则调用它。

我们后面用 **Solidity** 编写源码，再将源码编译成能由 **EVM（以太坊虚拟机）** 执行的字节码。你可以先把 EVM 想成“执行这类程序的运行环境”，类似 Python 解释器的角色，但运行规则不同。

### 3. 账户与地址：谁发起操作

可以把地址理解成一个公开的账户编号。一个常见的以太坊地址形如：

```text
0x1234567890abcdef1234567890abcdef12345678
```

这是**示例地址**，不要往这里转账。地址不等于真实身份，也不等于网站用户名。

常见的两类账户：

- **外部账户（EOA）**：通常由私钥控制，能发起交易。
- **合约账户**：地址对应链上代码和状态，响应调用。

### 4. 钱包：替你保管或使用密钥的工具

钱包不是一个真的“装 ETH 的文件夹”。余额由链上状态反映；钱包负责管理密钥、查看余额、构造交易以及请求签名。

可以记住下面的关系：

```text
私钥（秘密） ──用于签名──> 证明你授权了某笔交易
地址（公开） ────────────> 其他人用来识别链上账户
钱包（工具） ────────────> 帮你查看账户、发出签名请求
```

**绝不能把真实私钥、助记词放进代码、截图、聊天或 Git。** 本课程先使用 Remix 内置虚拟账户，不需要真实钱包。

### 5. 交易（Transaction）：请求网络改变状态

例如“计数器加 1”或“向合约付款”，通常要通过交易提交。

一笔典型的交易会经历：

```text
用户点击按钮
  → 钱包准备交易
  → 账户签名（证明授权）
  → RPC 节点接收并广播
  → 网络执行合约代码、记录结果
  → 交易被打包，应用读取回执确认结果
```

这里 **RPC 节点** 就像访问区块链的网络接口。它不是“区块链的总管理员”，也不能替你决定合约的权限规则。

**发出交易 ≠ 交易执行成功**。拿到交易哈希只能表示得到了一个标识，还要检查回执状态和所需确认程度。

### 6. Gas：让链上执行有成本

在传统 Flask 服务里，你可能为服务器付费；在以太坊这类链上，执行交易需要资源，系统用 **Gas** 计量。

用出租车类比：

- **Gas Used**：实际消耗了多少“计量单位”，类似实际行驶里程。
- **Gas Price**：每个单位要付多少钱，类似每公里单价。
- **Gas Limit**：这次交易最多愿意提供多少计算资源，类似给行程设一个上限。

粗略关系：

```text
交易执行费用 ≈ 实际 Gas Used × 实际有效 Gas Price
```

但不同网络的收费结构可能不同，还可能涉及 L2 数据费用等。**Gas 是计量单位，不直接等于 ETH，也不等于人民币。**

在 Remix VM 中使用的是**虚拟测试余额**，不会花真实资金。

## 两种操作：看数据和改数据

假设链上有一个计数器，当前数字是 0。

| 你做的事情 | 类比 Flask | 通常需要链上交易？ | 链上 Gas 费用？ |
| --- | --- | --- | --- |
| 看现在数字是几 | GET 查询 | 不需要 | 本地调用不向链支付 |
| 把数字加 1 | POST 更新 | 需要 | 交易执行时通常产生 |
| 修改失败并回滚 | 业务校验失败 | 仍可能已提交交易 | 已使用的 Gas 通常仍付费 |

注意，“只读免费”指典型的 **链下 eth_call 不付链上费用**，不代表提供 RPC 的服务商一定免费，也不代表 view 函数在链上被其他合约调用就没有计算成本。

## 和你熟悉的后端，对照理解

| 后端开发概念 | 链上类似概念 | 千万别误解 |
| --- | --- | --- |
| Python 函数 | Solidity 函数 | 写状态可能需要交易并消耗 Gas |
| 数据库表/记录 | 合约状态变量、mapping | 不是可任意 SQL 查询的数据库 |
| 用户登录信息 | 签名、调用者地址 | 地址不等于现实身份 |
| API 请求 | 合约调用 | 写操作需要关注交易确认 |
| 数据库事务回滚 | EVM 交易 revert | 失败交易的已消耗 Gas 不自动退还 |
| 日志 | 合约 event | event 主要用于观察，不是当前业务状态 |
| Celery / cron | 外部触发交易 | 合约不会自己在指定时间醒来 |

## 不用安装任何东西，做三个小判断

**问题 1：** 我把钱包 APP 卸载，链上的余额是不是就没了？

**问题 2：** 我在 Remix 中点击“读取数字”和“数字加 1”，哪一个更像数据库 SELECT，哪一个更像 UPDATE？

**问题 3：** 能不能把身份证号放在 Solidity 的 private 变量里，认为别人看不到？

<details>
<summary>点开参考答案（先自己想一遍）</summary>

1. 不是。链上的状态并不存放在 APP 里；但如果丢失了唯一的恢复方式，就可能无法再控制对应账户。
2. 读取类似 SELECT；加 1 类似 UPDATE。不过链上写入的签名、执行、收费和确认机制与数据库不同。
3. 不能。Solidity 的 private 限制合约代码内的访问方式，不是加密；链上数据可能被外部观察。
</details>
