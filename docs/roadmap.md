# 12 周智能合约学习路线

> 适合有 Python/Flask、数据库、API、Linux/Git 基础，希望从零接触智能合约的开发者。按每天约 1～2 小时规划，**不是学习成效保证**。

## 推荐按三条线路并行

**概念线（20%）**：区块链和传统后端的不同是什么？谁来执行代码？数据能否删除？

**代码线（50%）**：每个知识点必须能编译、能跑测试、能复现失败；避免只看视频。

**安全线（30%）**：每周至少回答一个问题：没有权限的人能否调用？谁能冻结资金？失败时是否会卡死？

## 为什么先选 Ethereum EVM / Solidity / Foundry？

这是学习主线，不表示其他生态不重要。**先把账户、交易、Gas、合约状态和测试学透**，后续再学 L2、跨链、DeFi、Move/Rust 生态，避免初学期同时切换三种执行模型。

## 你的现有后端经验可以迁移

- Python 函数与 REST API → Solidity external/public 与 ABI；但调用成本与错误语义不同。
- 数据库事务 → EVM 交易原子性；但链上写入昂贵、公开且难以删除。
- JWT/RBAC → 签名与 msg.sender；链上权限一般不能依赖 Web 用户名。
- pytest → Foundry Forge；需要额外的敌手视角与不变量测试。
- Celery 定时任务 → 链上不能自己定时执行，必须由外部交易触发。
