# 02-1 EVM、交易、Gas 与回滚

## 本课目标

解释：读链上数据、发送交易、执行智能合约、消耗 Gas、回滚失败之间是什么关系。

## 一笔交易发生了什么

```text
钱包构造交易 → 账户私钥签名 → RPC 广播
       ↓
网络验证交易是否合法（nonce、余额、签名、Gas 等）
       ↓
执行 EVM 字节码 → 更新状态 / 发出事件 / 消耗 Gas
       ↓
交易进入区块 → 查询交易回执和确认状态
```

交易提交成功（拿到交易哈希）**并不意味着执行成功**；要查看交易收据中的状态并理解最终确认/重组风险。

## Gas、费用与存储

Gas 是资源计量，不是固定法币价格。用户最终支付的链上执行费用通常与 `gasUsed` 和 `effectiveGasPrice` 有关，费用不一定等于你在钱包上填写的 Gas Limit 乘以最高出价。

- `eth_call`：在当前链状态上模拟读取/执行，不向链提交交易，通常无需链上支付 Gas。
- `eth_sendRawTransaction`：广播已签名交易，由网络决定是否接受并最终打包。
- `SSTORE`：写链上持久存储，通常较贵，应关注设计。
- `LOG`：发出事件便于链下索引，不是合约的内部数据库。

## 原子性与失败

如果交易在 EVM 执行过程中 revert，同一交易内的链上状态修改和事件日志被回滚，但**执行消耗的 Gas 不会免费退还**。这不同于 Python 后端直接 try/except 后手动修改数据库。
