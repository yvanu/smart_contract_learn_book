# 02-1 一笔交易从点击按钮到执行完成：EVM 与 Gas

> **本课目标**：弄懂你在 Remix 点击 increment 时究竟发生了什么，为什么有的操作不收费、有的交易失败了仍消耗 Gas。

## 从你刚才的 Remix 实验出发

你在 [00-2](/00-start/environment) 做了两件事：

- 点击 `number()`，马上得到当前数字。
- 点击 `increment()`，数字改变，终端里出现交易记录。

它们的区别不是“按钮颜色不同”，而是**是否要求区块链改变可持久化的状态**。

## 一笔写入交易的完整故事

```text
1. 你在界面点击 increment()
             ↓
2. 客户端构造交易：发起地址、合约地址、调用数据等
             ↓
3. 账户使用私钥签名（Remix VM 可代为模拟）
             ↓
4. 通过 RPC 把交易交给网络
             ↓
5. 节点验证交易基本规则、执行 EVM 代码
             ↓
6. 记录成功的状态变化和事件，形成交易回执
             ↓
7. 交易进入区块，应用检查执行状态及确认程度
```

这里的 **EVM** 就是执行合约字节码的虚拟机。与普通服务器不同，区块链网络需要多个参与者按照相同的规则得到一致结果，所以合约不能随意向互联网发送 HTTP 请求、读取本机随机文件或直接执行系统命令。

## 读调用为什么看似不用 Gas？

如果你通过 `eth_call` 查询 number，节点会在给定链状态上执行一个模拟调用，并把结果返回给你，但它**不作为一笔新的链上交易保存**，因此通常不需要支付链上交易费。

这不表示节点零成本：节点仍做计算，有些 RPC 服务商可能收 API 使用费。

如果合约 A 在**一笔真实交易中调用**合约 B 的 view 函数，执行计算仍会计入那笔交易的资源开销。

## Gas 到底怎么计算？先做一道算术题

记住三个词：

1. **Gas Limit**：为这笔交易设定的执行资源上限。
2. **Gas Used**：执行实际消耗的 Gas。
3. **Effective Gas Price**：每单位 Gas 最终适用的价格。

举一个**纯演算示例，不代表当前网络实时价格**：

```text
Gas Used = 21,000
Effective Gas Price = 20 gwei

执行费用 = 21,000 × 20 gwei
         = 420,000 gwei
         = 0.00042 ETH
```

说明：`1 gwei = 10^9 wei`，`1 ETH = 10^18 wei`。

为什么不能直接用“Gas Limit × 最高报价”作为最终费用？因为它是资源上限和最高出价相关参数，并不表示最终一定把上限全用完；另外不同网络的费用结构也可能不同。

## 为什么写状态常比读状态贵？

Solidity 的 `count += 1` 不只是 CPU 做了一次加法，它要读取、更新持久化状态。在 EVM 中，访问和修改状态需要计量相应操作的 Gas；首次写入、覆盖旧值、不同存储访问模式可能有不同费用。

你现在不需要背 Gas opcode 表，只需要建立设计意识：**不要在链上毫无必要地重复保存或遍历大量数据**。

## 失败交易发生什么？

假设非 owner 调用 reset，执行到：

```solidity
if (msg.sender != owner) revert Unauthorized();
```

执行会失败，当前交易内的链上状态修改回滚，相关事件也不会作为成功日志保留。但执行这些检查消耗的 Gas，通常仍会由交易支付。

需要区分两种情况：

- **发送前在本地模拟就检测到错误**：可能根本没有向链广播。
- **交易已经被网络打包，执行中 revert**：可在回执中查看失败状态与 Gas Used。

不要把所有 UI 报错都误认为“一定已经上链并收费”。

## 最常见的三个误解

| 误解 | 实际情况 |
| --- | --- |
| 我拿到了交易哈希，所以业务成功 | 不一定，还要看回执状态和确认情况 |
| view 是免费的，所以完全没有计算 | 链下不支付链上执行费，但节点仍在算 |
| 合约规定“明天退款”，明天就会自己执行 | 不会，届时仍需要有人发送触发交易 |

## Remix 再做一次对照实验

1. 在虚拟链部署 [OwnedCounter](/01-solidity/)。
2. 点击 `count()`，观察返回值。
3. 点击 `increase(3)`，观察成功交易记录和 Gas Used。
4. 切换到非 owner 地址调用 `reset()`，观察失败和错误信息。
5. 再读取 `count()`，确认失败不会把之前的 3 清掉。

写一段自己的记录：哪个步骤只读、哪个修改状态、哪个 revert、各有什么可观察证据。
